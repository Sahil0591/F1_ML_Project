# Probabilistic Race Models

Phase 8 implements bounded comparisons of scikit-learn histogram boosting,
XGBoost, LightGBM, and CatBoost. Real-world selection requires sufficient eligible
Gold coverage and independent paired folds. Test fixtures verify software
behavior and cannot establish model quality. Historical Core and prospective
registries follow the [Gold workflow](GOLD_WORKFLOW.md).

## Commands and optional dependencies

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,xgboost,catboost,lightgbm]"
.\.venv\Scripts\python.exe -m f1_ml_predictor model-hardware --workload-rows 32000
.\.venv\Scripts\python.exe -m f1_ml_predictor compare-models --tier Gold
.\.venv\Scripts\python.exe -m f1_ml_predictor compare-models --tier Development --backends hist --device cpu
```

Histogram boosting is always available through scikit-learn and always uses CPU.
Other libraries are optional extras, imported only when selected and installed.
Missing optional libraries are reported explicitly. The configurations use 80
trees, shallow depth or seven leaves, learning rate 0.05, fixed seeds, and one CPU
thread. No exhaustive search or random validation split is used. Defaults are
deliberately small; they are engineering starting points, not tuned F1 parameters.

`--min-train-events` defaults to two fit events. One additional earlier event is
reserved for calibration, so at least three prior complete labelled events are
needed for the first outer test cohort. `--seed` defaults to 42; `--draws` defaults
to 4096 and is bounded to 128 through 65536. Named cutoff kinds stay separate.

## Fit and calibration contract

The Phase 7 rolling-origin protocol gates both features and audited labels. A
training race is eligible only when every driver's label is known by the relevant
cutoff. All drivers remain together. Different cutoffs for the same event never
appear on opposing sides of a fold.

The latest eligible earlier events form the calibration window, selected by
`--calibration-events` (default one) while preserving minimum fit history.
Fit events must be strictly earlier, with complete labels available by the
earliest calibration prediction timestamp. Calibration labels must be available by the outer test
cutoff. Median imputation fits only on the fit events and remains frozen for
calibration and test prediction. There is no refit on the calibration race.

A position regressor learns observed audited position divided by field size.
Unknown positions do not become invented retirement labels. A DNF classifier
uses only observed Boolean DNF targets. With insufficient training classes,
DNF uses a smoothed prior from known labels, with its status and label count
recorded. With insufficient calibration classes, calibration stays identity.
Unknown DNS/DSQ DNF labels remain excluded from DNF fitting and scoring.
With zero known DNF targets, the Beta(1,1) prior is 0.5 and is explicitly marked
`insufficient_data_prior`. This is an unvalidated simulation assumption, not an
audited retirement estimate; it cannot satisfy DNF evaluation or model selection.

`--calibration` chooses sigmoid, isotonic, or identity DNF calibration. Sigmoid
requires ten known labels and two in each class. Isotonic requires 100 known
labels, ten in each class, and three distinct scores. Insufficient history skips
calibration with counts and a reason. Four fixed race-order temperatures
(0.5, 1, 2, 4) are compared on mean calibration-race winner log loss using common
seeded simulation draws. This is a small controlled
calibration comparison. A single calibration race is noisy and can overfit;
final marginal calibration is measured on outer test events.

`RaceModel.predict` accepts label-free feature rows for one complete event/cutoff
roster. The caller supplies the complete entered roster, as the benchmark builder
does. It rejects duplicate drivers, late features, evidence-tier or cutoff-kind
mismatches, fit/calibration events, and prediction cutoffs preceding calibration
label availability. Stored model artifacts must be trusted before joblib loading.

## Joint distributions and limits

For each draw, independent Bernoulli DNF states and a Plackett-Luce order are
sampled. The order is generated by Gumbel random utilities from the position
scores and calibrated temperature. Sampled finishers precede sampled retirees,
preserving the sampled order within each group. Every draw contains exactly one
driver at every position.

All published marginals come from these same draws. Winner probabilities are
the first-position column. Podium probabilities sum the first `min(3, field_size)`
columns. Each driver's finish distribution sums to one; each position column
sums to one across drivers. DNF probabilities count the sampled DNF states.
Expected position is the mean of the finish distribution.

Finish distribution means a total modeled order including trailing retirements.
It does not model FIA classified status, laps completed, DNS/DSQ, retirement time,
or official retirement ordinals. Retirees can occupy podium places in a simulated
race with fewer than three finishers. Independent DNF states omit shared crashes,
weather incidents, and constructor reliability correlation. These assumptions
need evaluation before championship simulation uses the joint model.

Finite simulation introduces sampling error. The per-marginal standard-error
upper bound is `0.5 / sqrt(draws)`, about 0.0078 at the default. This describes
Monte Carlo error, not model uncertainty or an accuracy guarantee. Composition
with DNF can alter winner/podium calibration, so evaluate the final marginals.

## Comparisons and provisional selection

Comparisons use the common outer race/cutoff cohorts available to every evaluated
candidate and the Phase 7 heuristic/logistic baselines. Reports include winner
categorical log loss, Brier score, top-1/top-3 accuracy, marginal calibration bins,
podium and DNF log loss/Brier/calibration, expected-position MAE, ranked probability
score, and pairwise ranking accuracy among observed positions.

Selection is separate for each named cutoff. The frozen
[Gold evaluation protocol](EVALUATION_PROTOCOL_V1.md) requires 15 distinct paired
Gold test races for preliminary comparison and at least 25 eligible Gold races
with 25 distinct paired outer test races for selection, evaluated metrics for every
task, and no recorded regression
against either baseline in winner log loss/Brier/top-N accuracy, podium/DNF log
loss/Brier, or position MAE. Missing comparison metrics also block selection.
Among passing candidates, lowest winner log loss wins. This strict default can
retain deferred selection; all regressions remain visible for later review.

A selected configuration is provisional. Choosing it on outer comparison scores
does not make those scores an unbiased estimate of the selected model's accuracy.
Future independent races must confirm it. Only Gold can support primary accuracy
claims; Silver and Development remain exploratory. Empty tiers produce no metrics,
no fitted model, and no selected backend.

## Artifacts and provenance

Hardware reports go to `models/experiments/hardware.json`. Tier comparison reports
go to `models/experiments/<tier>/comparison.json`; fitted fold models go to its
`fitted` directory. Prediction Parquet goes to
`data/predictions/probabilistic/<tier>.parquet`. All remain ignored by git.

The file evaluator verifies the dataset's declared name, SHA-256, row count,
predictor list, and coverage hash against the Phase 6 manifest before fitting.
Reports bind dataset and manifest hashes, prediction and fitted-artifact hashes,
model-source hashes, git commit, library versions, seed, draw count, fit/calibration
events and row indices, label-availability maxima, model parameters, calibration
losses/status, elapsed fit time, and actual CPU/GPU device and fallback reason.
Source hashes identify code even for a run made before its commit.
An estimator's NaN missing-value parameter is serialized as the explicit typed
marker `{"type": "float", "value": "NaN"}`. Metrics still require finite strict
JSON values; this encoding applies only to backend configuration.

The first eight-race Gold Core evaluation and observation counts are recorded in
[Gold workflow](GOLD_WORKFLOW.md). Four CPU backends completed the same five paired
test races. Selection remains deferred, with no validated championship model.

## GPU detection and measured policy

GPU checks are explicit through `model-hardware`, never part of the normal offline
test suite. Probes query `nvidia-smi`, `nvcc`, and Windows CUDA driver/runtime APIs,
then fit both estimator tasks in isolated processes with bounded timeouts.
XGBoost's build metadata and fitted booster configuration verify CUDA use and
detect silent CPU fallback. CatBoost's actual GPU fits verify usable support.
LightGBM probes both CUDA and OpenCL GPU devices; an unsupported build remains CPU.
No CUDA toolkit, compiler, driver, or custom LightGBM build is installed by this phase.

The 2026-09-28 checks found NVIDIA GeForce RTX 3050 Laptop GPU, 4096 MiB, compute
capability 8.6, driver 616.56, driver API 13.4, installed toolkit 12.9.41, and
standalone toolkit runtime API 12.9. XGBoost 3.4.1 reports CUDA build version 13.3
and passed CUDA fits. CatBoost 1.2.10 passed GPU fits. LightGBM 4.7.0's installed
Windows wheel supports neither CUDA nor OpenCL GPU training. Scikit-learn 1.9.1,
NumPy 2.5.3, and SciPy 1.18.1 were also recorded.

Controlled synthetic timings used 32 numeric features, 80 trees, two consecutive
repeats, and both position and DNF fits plus small predictions. These are training
timings, not race accuracy or a representative F1 validation dataset.

| Backend | 32,000-row CPU median | GPU median | Device conclusion |
| --- | --- | --- | --- |
| Histogram boosting | 0.784 s | Unsupported | CPU |
| XGBoost | 0.883 s | 0.633 s | CUDA usable; about 28% faster at this workload |
| LightGBM | 0.705 s | Unsupported build | CPU |
| CatBoost | 2.158 s | 1.161 s | GPU usable; about 46% faster at this workload |

The latest 8,000-row refresh measured approximately 5% improvement for XGBoost
and slower CatBoost GPU fits, below the policy threshold. `--device auto` requires a report captured
within 24 hours with matching installed library versions, at least the benchmark's
row count, and measured GPU fit time at least 15% below CPU. Otherwise it uses CPU.
The latest local report uses the 8,000-row workload. Refresh probes after hardware,
driver, or library changes. `--device cuda` requests GPU only after a successful
probe, and unsupported devices or actual GPU fit failures fall back to CPU with
explicit reasons. Every fitted fold records the device actually used.

Seeds and single CPU threads support repeatable CPU runs. GPU floating-point
summation can differ, particularly for CatBoost; fixed seeds do not promise
bitwise GPU reproducibility. Driver/toolkit/runtime/build versions are distinct
and retained separately.
